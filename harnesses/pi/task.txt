Use the official Pi subagent extension and its role-based workflow:
1. Begin with one parallel subagent call containing four scout tasks:
   - requirements completeness and missing features;
   - backend, database schema, security, and core business flows;
   - frontend completeness and frontend-backend API mismatches;
   - build, tests, reproducibility, placeholders, mocks, and likely failures.
2. Give the consolidated scout findings to the planner agent.
3. Use the worker agent to implement the prioritized plan.
4. Use the reviewer agent to independently review the resulting code for correctness, security, requirement coverage, regressions, and missing tests.
5. Use the worker agent once more to address actionable review findings.
6. The main agent remains responsible for integration, additional fixes inside the repository, final tests, and reviewing the complete Git diff.

Use no more than eight subagent executions in total. Keep parallel agents read-only unless they are workers. Never run multiple writing workers concurrently.
