# 发布脱敏说明

## 原则

发布副本通过“白名单复制”生成，不直接把本地评测目录推送到 GitHub。所有缓存、构建物、密钥和原始大轨迹默认不进入发布目录。

## 已做处理

- 项目展示名统一替换为“通用物料管理系统 / Generic Material Management System”。
- 需求中的个人称谓替换为“示例 CIS 元件库”。
- Word 需求原件移除组织/人员标识、识别性总览图和重复进度截图。
- 进度表删除日期栏，仅保留功能名称、功能项和备注。
- 清理 Word 及内嵌 Visio 的作者、修改者、公司、自定义属性和修订标识等元数据。
- 同步删除 Markdown 拆包中对应的识别性图片，避免原图绕过正文脱敏。
- 排除 API Key、`.env`、Token、私钥、数据库备份和浏览器状态。
- 排除 `node_modules`、Maven `target`、npm/Maven 缓存和运行日志。
- 排除 Pi 约 788 MiB 的完整轨迹。
- 排除候选与 worktree 的嵌套 `.git` 元数据。

## 为可复现性保留的内容

- Java 包名 `com.koolearn.bms` 作为历史技术命名保留。批量重命名会引入大量与 Agent 结果无关的功能性改动。
- 测试账号与默认密码保留为明确的本地演示值，不能用于生产。
- DingTalk、CIS 和数据库的默认配置均为 demo 或 localhost。
- 本机绝对路径统一替换为 `/workspace/material-system` 和 `/home/evaluator` 等通用占位路径。

## 对候选身份的影响

评分针对通用化之前冻结的候选树。发布版只进行了展示字符串和需求称谓替换，没有修复任何候选缺陷。原始提交与树哈希记录在验收报告中；发布副本因脱敏替换会产生新的 Git 哈希。
